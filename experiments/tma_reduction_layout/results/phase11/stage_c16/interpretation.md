# C1.6 结果解释

本轮支持“完整 kernel 的片上工作与数据传输存在重叠，不同布局跨越不同瓶颈区间”的解释。
证据来自新 cohort 的复现、独立搬运对照、真实 DRAM/L2 counter 和单 kernel Graph 校验。
当前范围是 H100、原 host-created descriptor、两个既有几何及其八个布局，不是跨形状或跨架构泛化。

## 冻结模型的复现

沿用 C1.5 的片上增量代理及 CTA 倍率，不调整固定项 26.6 us、平台 61.4/56.1 us。
三个新 worker 的 warm 时间中位数：

| 配置 | vec1 | vec2 | vec4 | vec8 |
|---|---:|---:|---:|---:|
| 32×64/w8 | 60.592 | 61.504 | 68.224 | 111.120 |
| 32×128/w4 | 55.264 | 55.456 | 55.584 | 56.768 |

单位 us。八点最大预测误差 1.51%，均在事先记录的 3% 参考范围内。
这是模型在新运行 cohort 上的复现，八个布局本身已被观察过，不能称为 unseen-shape 验证。

## 支持 HBM/传输平台的独立证据

32×128 的搬运对照为 54.672 us，完整 kernel 为 55.264–56.768 us。
NCU warm 实测四个完整 kernel 的 DRAM sustained-peak 利用率为 84.68–86.18%，
对照为 87.37%；DRAM 实际读量均约 128 MiB，L2 sector hit 约 6.5%。
这些结果支持这一组接近 HBM 带宽限制，而不是仅依据时间平坦推断。

32×64 的对照为 58.688 us，vec1/vec2 分别为 60.592/61.504 us，
显示明显传输平台特征，但仍有约 1.9–2.8 us 的额外成本，不能说完全被理想平台钳位。
vec4/vec8 的 warm DRAM 利用率降至 67.70%/40.87%，实测时间显著超过搬运对照。
结合 C1.5 的规约斜率与通信计数，结果支持片上规约路径对慢布局的影响。
没有把 SM throughput 指标直接当作算术单元饱和率，也没有声称分离了每条指令的成本。

## 片上增量并非直接 event 提交间隙伪造

一个额外 worker 做 800 个 direct/Graph 配对样本。API 核对每个图恰好包含一个原 kernel
与两个外部 event record 节点，无批量除次数，全部十个 binary 的输出检查通过。
direct event 比 Graph 内 event 多约 3.4–4.6 us；差异也包含 Graph 调度影响，不能全部称为纯 CPU 时间。

32×64 的 Graph warm vec4→vec8 增量为 43.344 us，C1.5 预测为 43.198 us，相差约 0.34%。
因此此前接近一比一的增量并未因去除主机提交间隙而消失。
不过 26.6 us 固定项包含了计时方法影响，不能直接称为纯设备开销。

## 尚未解决的部分

若平台改用独立 TMA 对照，在同一 worker 上重测微基准，并仅用 N64/vec4 一个完整 kernel 点
校准 offset，则剩余七个点的 warm 最大误差为 4.37–4.78%。
校准 offset 为 25.263–26.611 us；它仍然是经验残差，不是独立隔离的物理延迟。
单点校准后的模型没有对全部七点达到 3% 精度。微基准仍包含私有更新、累加、循环和资源变化。

清缓存后的实际 DRAM 读量仍约 128 MiB，写量从约 10.4–10.9 MiB 增至 27.1–27.9 MiB。
这项干预改变了写回压力，不能归结为只改变目标输入读命中率；也不能将计数中的全部写量
归因于 kernel 的 8 MiB 逻辑输出。冻结的 warm 平台不自动适用于这种不同的内存状态。

当前证据支持所提出的瓶颈切换解释，并增强了 C1.5 片上增量的可信度；
完整、可迁移的 layout 选择模型仍需独立成本校准和新形状验证。本轮不启动 C2。

所有原始 event 样本、NCU 报告、compiler artifacts、失败记录和源码修订均保留。
仅两个新搬运对照，24 个旧 CUBIN 原样复用，没有 native 重编译。完成本阶段后单独 commit。
