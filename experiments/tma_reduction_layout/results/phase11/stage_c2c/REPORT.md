# Stage C2c — 单次组合、固定 R 局部对照与资源补测

日期：2026-10-18。H100 sm90，原 host-created descriptor、BF16→FP32 max，沿 M 规约。

**采集与证据校验已完成；独立物理底座与纯传输分量尚未辨识。** 相同 q 下，允许每个几何/worker 单独拟合一个公共非负 B，仍有 37/45 组不能在全部布局上闭合到 3%。因此不把完整对照减去一个经验常数，不把全图截距加入静态选择器，也不把拟合残差命名为纯硬件延迟。

## 1. 实验与保护范围

- CPU 预检覆盖 228 个逻辑程序；25 个原 CUBIN 逐字节复用，其余使用持久 Triton 缓存。native SHA 与 pinned compiler 保持一致，ccache 统计未改变，没有重新构建 Triton。
- GPU 正确性检查 1704 项全部通过；包含 quarter/random/boundary 输入。固定 R 的随机 FP32 checksum 允许已记录的舍入容差，其余检查采用数值相等。
- 3 次固定调用，每测量单元 12 个单 kernel Graph 内事件样本，3 次交错访问；不使用 NCU duration 训练。自然驻留别名和相同 CUBIN 复用，未按结果重复测量。
- 原始 NCU 报告 22 份，软件动态采集 256 次，硬件计数采集 348 次；全部重新导入并绑定 CUBIN。
- 保留首次 CPU 预检失败、所有技术修订和源快照。第一次失败是 fixed-R 的嵌套 SliceLayout 扩维轴顺序，发生在分配 GPU 之前。
- 11 个 D1 几何已在补测前保护；未编译、加载、采集或计时其候选布局。旧 C3/C3.1 和全部既有 raw/compiler artifacts 保持原样。

标定几何：`8×64/w8, 8×128/w4, 8×256/w4, 16×64/w4, 16×128/w4, 32×64/w8, 32×128/w4, 64×64/w8`。另两个非 D1 的 R128/256 几何只用于单次程序资源标定。

## 3. 单次与稳态的组合检验

`MC` 采用驻留双槽与可观察的逐次输出；K1 只搬入一个 tile，K>1 搬入两个固定 tile。`FULL/TRANSFER` 的多 K 版本逐次搬入新 origin，槽位复用前的 K−1 次 barrier 属于显式 fixture；真正单次程序没有运行时 K 循环。单独测 ROW 与 direct-row SCAFFOLD，不将其当作已知纯底座。

## 4. 固定 R 的同语义配对局部对照

R4/8/16/32，共 18 组合法 `(p,columns)`，每组四个版本：native、wide、fixture、fixture_wide。每线程逻辑元素数与输入状态更新固定，四个版本使用相同 checksum consumer，并在循环后观察全部最终状态。native/wide 对同一分组计算相同 max；wide 采用精确的 ×2、max、×0.5 来阻断 BF16 max 识别，其额外操作通过对应 fixture 对照保留。

跨 p 改变的是待研究的局部分组，不声称不同分组具有相同完整算子语义。native−fixture、wide−fixture_wide 和双重差分为有效子图对照，包含指令调度/打包/转换交互，不能直接命名为裸 max 指令延迟。自然条件若寄存器分配导致 q 不同，明确标为驻留不匹配；受控 q 对照另列。

| R32，q=4 | native−fixture ns | wide−fixture_wide ns | 双重差分 ns |
|---|---:|---:|---:|
| p=1, columns=32 | -0.01 | -0.06 | 0.05 |
| p=2, columns=16 | 2.45 | 34.56 | -32.10 |
| p=4, columns=8 | 7.00 | 56.53 | -49.51 |
| p=8, columns=4 | 2.95 | 61.75 | -58.80 |
| p=16, columns=2 | 10.97 | 71.78 | -60.84 |
| p=32, columns=1 | 25.28 | 70.29 | -45.01 |

p=1 的 max-deleted 对照应接近零差值，保留微小正负值，不截断成纯正惩罚。各 R、各 p、全部 q 与 worker 数值在 analysis.json 中保留。

### BF16 标量干预未成功，不能据此辨识 packing 单项

另外新增 4 个 p=2 BF16 scalar combine 程序，复用 16 个 native/wide/fixture CUBIN，重新配对采集 3 次调用、34,560 个 Graph 事件样本、2 份 NCU 报告与 180 项正确性检查。PTX 的 scalar max site 数确实为 native packed site 的 2 倍，但 NCU 显示实际 max 执行次数相同：

| R / p=2 | native 动态 max/iteration/CTA | scalar-source 动态 max | wide FP32 动态 max |
|---|---:|---:|---:|
| 4 | 4 | 4 | 8 |
| 8 | 8 | 8 | 16 |
| 16 | 16 | 16 | 32 |
| 32 | 32 | 32 | 64 |

后端将 scalar PTX 重新合并为 HMNMX2.BF16_V2，原先期望的 scalar max = 2×native 检查明确失败，保存在 packing_supplement/validation_attempts，未通过改名把它包装成成功干预。另 8 个 CPU-only 修订（max+cvt 同 asm、显式复制 BF16 halves）仍生成打包 SASS，未继续 GPU 计时。保留源快照、一次上传失败和一次 SliceLayout 编译失败，不修改原始 compiler artifacts。

**因此尚未独立辨识 packing 与 widening 的裸成本。** fixed-R native/fixture 对比是可用的净局部子图对照；packing supplement 的 scalar−native 微小计时差只反映最终实现/调度差异，不能解释成打包收益。C3.2 使用净子图响应，不给 packing 指令人为指定延迟。全阶段共 305,748 个 Graph 事件样本、24 份原始 NCU 报告并逐份本地重导入。

## 5. 物理寄存器与边界

| 非 D1 单次程序 | R | vec8 n_regs | local bytes |
|---|---:|---:|---:|
| 128×256/w8 | 128 | 43 | 0 |
| 128×512/w8 | 256 | 45 | 0 |

固定 R 的人工 state/consumer fixture 与单次完整程序具有不同活跃区间；资源模型必须按程序族校准。例如 R32/p16/columns2 的 native 与 wide 静态分配分别为 72 与 111 个寄存器，而 R256 的单次 vec8 程序只分配 45 个。这些是实际编译分配与 CUDA attribute 证据，不等价于逻辑元素存储量，也不能把“未观察到 spill”外推成任何布局均无 spill。

## 6. 交付与停点

本阶段只新增 C2c 证据。C3.2 的方法在正式 GPU 数据之前通过 C32_method_binding.json 绑定；下一阶段更新静态组合与资源模型、构造单侧配对不确定性，并冻结分层预测。D1 尚未开始。
